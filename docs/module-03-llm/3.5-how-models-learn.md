Throughout Module 3, we explored how a Transformer processes tokens: tokens become [vectors](../glossary.md#vector), [attention](../glossary.md#attention) weighs relationships, [matrices](../glossary.md#matrix) transform information, and [softmax](../glossary.md#softmax) generates next-token probabilities.

Every step relies on [**weights and biases**](../glossary.md#weights-and-biases)—billions of floating-point numbers inside the model's matrices.

This raises the most important question in AI: **Where do those numbers come from?**

No human programmer types them in. A model begins with completely random numbers and **learns** the right values through training. This lesson explains how that training process works, from loss functions to RLHF.

---

## 1. The Forward Pass vs. The Training Loop

When using a model to generate text, information flows in one direction:

$$\text{Tokens} \longrightarrow \text{Embeddings} \longrightarrow \text{Transformer Layers} \longrightarrow \text{Logits} \longrightarrow \text{Probabilities}$$

This is called the **forward pass** (or *inference*).

During training, we add a feedback loop:

1. **Forward Pass:** The model predicts probabilities for the next token.
2. **Compute Loss:** We compare the model's prediction against the *actual* next token in real text.
3. **Compute Gradients (Backward Pass):** We calculate how much each weight contributed to the error.
4. **Update Weights:** We adjust the weights slightly so the model makes a better prediction next time.

```text
┌────────────────┐     ┌───────────────┐     ┌────────────────┐
│  Forward Pass  │ ──> │ Compute Loss  │ ──> │ Backward Pass  │
│  (predict next)│     │(measure error)│     │  (gradients)   │
└────────────────┘     └───────────────┘     └────────────────┘
        ▲                                             │
        └────────────── Update Weights ───────────────┘
```

## 2. Measuring Mistakes: The Loss Function

To improve, a model needs a clear score measuring how wrong it was. This metric is called the **Loss**.

For next-token prediction, modern LLMs use **Cross-Entropy Loss**. Suppose the true next word in a sentence is `"cat"`. We look up what probability the model assigned to `"cat"`:

$$\text{Loss} = -\ln(P(\text{correct token}))$$

- If the model is confident and correct ($P = 0.99$), $-\ln(0.99) \approx 0.01$ (nearly zero loss).
- If the model is unsure ($P = 0.10$), $-\ln(0.10) \approx 2.30$ (higher loss).
- If the model assigns near-zero chance to the correct token ($P = 0.001$), $-\ln(0.001) \approx 6.91$ (very high loss penalty).

Let's compute cross-entropy loss in Python using NumPy:

```python
import numpy as np

def cross_entropy_loss(probabilities, target_index):
    """Computes cross-entropy loss for the target token."""
    target_prob = probabilities[target_index]
    # Add a tiny epsilon to prevent log(0)
    eps = 1e-12
    return -np.log(target_prob + eps)

# Simulated probabilities over 4 vocabulary tokens: ["the", "dog", "cat", "runs"]
vocab = ["the", "dog", "cat", "runs"]
target_idx = 2  # Target token is "cat"

# Model A is confident and correct
probs_a = np.array([0.05, 0.05, 0.85, 0.05])
loss_a = cross_entropy_loss(probs_a, target_idx)

# Model B is guessing randomly
probs_b = np.array([0.25, 0.25, 0.25, 0.25])
loss_b = cross_entropy_loss(probs_b, target_idx)

# Model C is confident but WRONG
probs_c = np.array([0.80, 0.15, 0.02, 0.03])
loss_c = cross_entropy_loss(probs_c, target_idx)

print(f"Model A (confident & right): Loss = {loss_a:.4f}")
print(f"Model B (random guess):     Loss = {loss_b:.4f}")
print(f"Model C (confidently wrong): Loss = {loss_c:.4f}")
```

Running this prints:

```text
Model A (confident & right): Loss = 0.1625
Model B (random guess):     Loss = 1.3863
Model C (confidently wrong): Loss = 3.9120
```

The lower the loss, the better the model's predictions. The goal of training is to adjust the model's weights to minimize this loss across trillions of words.

## 3. Gradients and Gradient Descent

How do we know whether to make a weight bigger or smaller to reduce the loss?

Imagine standing on a foggy hillside trying to reach the bottom of a valley. You can't see the whole landscape, but you can feel the slope right under your feet. If the ground slopes down to the left, you step left.

In mathematics, that slope is called the **gradient**. The gradient of the loss with respect to a weight tells us: *"If we increase this weight by a tiny amount, does the loss go up or down?"*

Using **Gradient Descent**, we update each weight in the opposite direction of the gradient:

$$W_{\text{new}} = W_{\text{old}} - (\eta \cdot \text{gradient})$$

The parameter $\eta$ (Greek letter *eta*) is the **learning rate**—a small number (like `0.001` or `0.01`) controlling how big of a step we take.

Here is a simplified demonstration of gradient descent optimizing a single weight to predict a target value:

```python
import numpy as np

# We want our model to predict y = 6.0 when given x = 2.0 (ideal weight = 3.0)
x = 2.0
y_true = 6.0

# Start with a random initial weight
weight = 0.5
learning_rate = 0.05

print(f"Initial weight: {weight:.4f}")

for step in range(1, 6):
    # Forward pass: prediction
    y_pred = weight * x
    
    # Mean squared error loss: (y_pred - y_true)^2
    loss = (y_pred - y_true) ** 2
    
    # Calculus gradient: d(Loss)/d(weight) = 2 * (y_pred - y_true) * x
    gradient = 2 * (y_pred - y_true) * x
    
    # Gradient descent update step
    weight = weight - (learning_rate * gradient)
    
    print(f"Step {step}: Pred={y_pred:.2f}, Loss={loss:.4f}, New Weight={weight:.4f}")
```

Running this prints:

```text
Initial weight: 0.5000
Step 1: Pred=1.00, Loss=25.0000, New Weight=1.5000
Step 2: Pred=3.00, Loss=9.0000, New Weight=2.1000
Step 3: Pred=4.20, Loss=3.2400, New Weight=2.4600
Step 4: Pred=4.92, Loss=1.1664, New Weight=2.6760
Step 5: Pred=5.35, Loss=0.4200, New Weight=2.8056
```

In a full LLM, instead of 1 weight, this exact calculation is performed in parallel across hundreds of billions of parameters using an algorithm called **Backpropagation**.

## 4. Pre-Training vs. Post-Training

Modern AI models are not trained in a single pass. Training occurs in distinct stages:

### Phase 1: Pre-Training (The Autocomplete Engine)
- **Data:** Hundreds of billions of tokens scraped from web pages, books, code repositories, and articles.
- **Task:** Pure next-token prediction.
- **Result:** A **Base Model**. The base model understands grammar, facts, reasoning patterns, and coding syntax, but it doesn't behave like a helpful assistant.
- If you ask a base model:
  > *"What is the capital of France?"*
  
  It might respond:
  > *"What is the capital of Germany? What is the capital of Italy?"*
  
  Because on the web, questions often appear in lists or homework quizzes!

### Phase 2: Post-Training (Teaching the Model to Assist)
To turn an autocomplete engine into a conversational assistant (like ChatGPT, Claude, or Gemini), two further steps are applied:

1. **Supervised Fine-Tuning (SFT):** The model is trained on curated question-and-answer pairs formatted as dialogue (`<User>: ... <Assistant>: ...`). This teaches the model to answer queries rather than simply continuing text.
2. **Reinforcement Learning from Human Feedback (RLHF):** Humans evaluate multiple responses generated by the model, ranking which ones are helpful, accurate, and safe. An optimization algorithm (such as PPO or DPO) nudges the model's weights to favor preferred responses.

---

## 5. Why Training Matters for Prompts and Agents

Understanding training demystifies how models respond to prompts in Modules 4, 5, and 6:

- An LLM doesn't have emotions or intentions; it produces tokens that match patterns reinforced during pre-training and RLHF.
- A **System Prompt** works because post-training taught the model that tokens appearing under system tags represent rules that take priority over standard user text.
- When an AI hallucinates, it's not "lying"—it's generating tokens that are statistically plausible given the context, even if factually untrue.
